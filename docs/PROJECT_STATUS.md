## 6. Правила работы и безопасности

1. Одна задача → один мастер-промпт → реализация Claude Code → тесты → финальный отчёт → PASS/FAIL → обновление этого файла.
2. Не запускать все задачи одновременно; не смешивать Buddy, hotfix и UI 2.0 в одном релизе.
3. Не возвращаться к CLOSED без нового конкретного бага.
4. Новые задачи дописывать в backlog, не теряя существующие.
5. Не делать production switch, production Supabase migrations, рестарты рабочих сервисов, удаления данных или backup, изменений SSH/Nginx, force-push и прочих опасных действий без отдельного разрешения владельца.
6. Сохранять действующий rollback, backups и backup policy; VPS backup не заменяет Supabase PostgreSQL backup.
7. Работать в отдельных ветках/worktrees, проверять `origin` (в локальных worktrees он может ссылаться на `C:\KinoLuma`).
8. Статусы CLOSED присваивать только по подтверждённым отчётам, а не по предположениям.
